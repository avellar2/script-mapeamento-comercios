# Processo para bugs
- Primeiro investigar causa raiz. Confidence: 0.95
- Reproduzir o problema ou explicar por que nao foi possivel. Confidence: 0.90
- Nao fazer remendo superficial. Confidence: 0.95
- Nao alterar varios modulos sem plano. Confidence: 0.90
- Fazer mudancas pequenas, seguras e revisaveis. Confidence: 0.90
- Validar com teste. Confidence: 0.95
- Gerar relatorio final objetivo. Confidence: 0.95

# Relatorio final obrigatorio
- Todo relatorio final deve conter: objetivo da alteracao ou causa do bug. Confidence: 0.95
- Arquivos alterados. Confidence: 0.95
- Comandos executados. Confidence: 0.90
- Resultado dos testes. Confidence: 0.95
- Se houve scraping real, escrita real no Supabase, envio real de WhatsApp ou envio real de e-mail. Confidence: 0.99
- Se houve criacao/liberacao/finalizacao de reserva. Confidence: 0.95
- Quantos leads foram afetados, se aplicavel. Confidence: 0.90
- Dados sensiveis mascarados. Confidence: 0.95
- Hash do commit, se houver. Confidence: 0.95
- Status do push, se houver. Confidence: 0.95
- Riscos restantes e proximos passos recomendados. Confidence: 0.90

# Ferramentas autorizadas
- Command Code e a ferramenta autorizada para editar codigo, rodar testes, criar commits e fazer push quando solicitado. Confidence: 0.95
- Command Code deve ser usado para: edicao de codigo, refatoracao, correcao de bugs, implementacao de features, testes, commits e push. Confidence: 0.90
